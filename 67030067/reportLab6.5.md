
# Lab 6.5: Wi-Fi SoftAP & TCP Server for Attendance Tracking

## ผลการทดลอง

จากการทดลองสร้างระบบ Wi-Fi Access Point (SoftAP) ด้วย ESP32 เพื่อใช้เป็นพื้นฐานสำหรับระบบตรวจสอบระยะใกล้ของอุปกรณ์ โดยใช้ค่า RSSI ร่วมกับ TCP Server สำหรับรับส่งข้อมูล

ผลการทดลองพบว่า ESP32 สามารถสร้างเครือข่าย Wi-Fi ได้สำเร็จ และเปิด TCP Server เพื่อรอรับการเชื่อมต่อจากอุปกรณ์อื่นได้ โดยทดสอบผ่านคำสั่ง `nc` และสามารถเชื่อมต่อพร้อมรับข้อความตอบกลับ `Hello ESP32` ได้สำเร็จ

## ข้อมูลการตั้งค่าระบบ

| รายการ | ผลการทดลอง |
|---|---|
| Project Name | `wifi_softap_tracking` |
| ESP-IDF Version | v5.1.2 |
| Wi-Fi Mode | SoftAP |
| SSID | `MY_ESP32_AP` |
| Channel | 1 |
| IP Address | `192.168.4.1` |
| TCP Server Port | 8080 |
| DHCP Server | Started successfully |
| TCP Connection | Succeeded |
| Server Response | `Hello ESP32` |

## ผลการทดสอบ TCP Server

ใช้คำสั่งต่อไปนี้เพื่อเชื่อมต่อกับ TCP Server ผ่าน Terminal

```bash
nc -v 192.168.4.1 8080
```

ผลลัพธ์ที่ได้

```text
Connection to 192.168.4.1 port 8080 [tcp/http-alt] succeeded!
Hello ESP32
```

จากผลการทดสอบพบว่าสามารถเชื่อมต่อกับ ESP32 ผ่าน IP Address `192.168.4.1` และ Port `8080` ได้สำเร็จ พร้อมได้รับข้อความตอบกลับจาก Server

## คำถามท้ายการทดลอง

**1. การใช้ RF Signal Proximity (RSSI) ร่วมกับ HTTP Web Server บน ESP32 แก้ปัญหาการฝากเช็กชื่อแทนกันในห้องเรียนได้อย่างไร?**

ตอบ โดยใช้ค่า RSSI ประเมินความใกล้ของอุปกรณ์กับ ESP32 และใช้ HTTP Web Server สำหรับแสดงผลการเช็กชื่อ ช่วยตรวจสอบว่าอุปกรณ์อยู่ใกล้จุดเช็กชื่อจริงหรือไม่ แต่ไม่สามารถป้องกันการฝากเช็กชื่อได้อย่างสมบูรณ์

**2. เหตุใดระดับเกณฑ์ RSSI ที่ -55 dBm จึงเหมาะสมสำหรับการระบุตำแหน่งอุปกรณ์ให้อยู่ภายในรัศมีโต๊ะปฏิบัติการ?**

ตอบ เพราะค่า RSSI ประมาณ -55 dBm แสดงว่าสัญญาณค่อนข้างแรง จึงสามารถใช้เป็นเกณฑ์เบื้องต้นในการประเมินว่าอุปกรณ์อยู่ใกล้ ESP32 อย่างไรก็ตาม ค่านี้อาจเปลี่ยนแปลงตามสิ่งกีดขวางและสภาพแวดล้อม จึงควรทดสอบและปรับเกณฑ์ให้เหมาะสมกับพื้นที่จริง

**3. หากต้องการต่อยอดมินิโปรเจกต์นี้ในอนาคต ให้สามารถบันทึกข้อมูลการเข้าเรียนลงระบบ Cloud (เช่น Google Sheets หรือ Firebase) จะต้องเพิ่มส่วนเชื่อมต่อใดบ้าง?**

ตอบ ต้องเพิ่มส่วนเชื่อมต่ออินเทอร์เน็ตและ API สำหรับส่งข้อมูลจาก ESP32 ไปยัง Cloud เช่น Google Sheets API หรือ Firebase SDK พร้อมกำหนดรูปแบบข้อมูลการเข้าเรียน เช่น รหัสนักศึกษา วัน เวลา และสถานะการเข้าเรียน รวมถึงระบบยืนยันตัวตนและรักษาความปลอดภัยของข้อมูล

## สรุปผลการทดลอง

จากการทดลองพบว่า ESP32 สามารถสร้างเครือข่าย Wi-Fi ในโหมด SoftAP และเปิด TCP Server ได้สำเร็จ สามารถเชื่อมต่อผ่าน IP Address และ Port ที่กำหนด พร้อมส่งข้อความตอบกลับได้ จึงสามารถนำไปพัฒนาต่อยอดเป็นระบบตรวจสอบระยะใกล้และระบบเช็กชื่อเข้าเรียนได้
