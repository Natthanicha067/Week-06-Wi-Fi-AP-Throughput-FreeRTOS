
# Lab 6.4: IoT Sensor Dashboard

## ผลการทดลอง

จากการทดลองสร้างระบบ IoT Sensor Dashboard โดยใช้ ESP32 ทำงานร่วมกับ SoftAP, FreeRTOS Queue และ HTTP Server เพื่อรวบรวมข้อมูลเซนเซอร์และแสดงผลผ่านหน้าเว็บไซต์

ระบบประกอบด้วยการทำงานหลักดังนี้

1. **SoftAP** ทำหน้าที่สร้างเครือข่าย Wi-Fi ชื่อ `MY_ESP32_SENSOR_AP` เพื่อให้อุปกรณ์เชื่อมต่อ
2. **Sensor Task** ทำหน้าที่รวบรวมข้อมูลอุณหภูมิ ความชื้น และความเข้มแสง แล้วส่งข้อมูลเข้า FreeRTOS Queue
3. **Network Task** ทำหน้าที่รับข้อมูลจาก Queue และอัปเดตข้อมูลล่าสุดไว้ในตัวแปร `g_latest_data` โดยใช้ Mutex ป้องกันการเข้าถึงข้อมูลพร้อมกัน
4. **HTTP Server** ทำหน้าที่ให้บริการหน้า Dashboard และ API สำหรับเรียกดูข้อมูลเซนเซอร์

ผลการทดลองพบว่าระบบสามารถเริ่มต้น SoftAP และ HTTP Server ได้สำเร็จ พร้อมทั้ง Sensor Task และ Network Task สามารถรับส่งข้อมูลผ่าน Queue ได้อย่างต่อเนื่อง

## คำถามท้ายการทดลอง

**1. เหตุใดจึงต้องใช้ Mutex ในการป้องกันการเข้าถึงตัวแปร g_latest_data ร่วมกันระหว่าง vNetworkTask และ HTTP Handler? ถ้าไม่ใช้จะเกิดอะไรขึ้น?**

ตอบ เพราะ Mutex ช่วยป้องกันไม่ให้หลาย Task เข้าถึงหรือแก้ไขตัวแปร `g_latest_data` พร้อมกัน หากไม่ใช้ อาจเกิด Race Condition ทำให้ข้อมูลไม่ถูกต้องหรือไม่สอดคล้องกัน

**2. esp_http_server รัน Handler บน Thread ใด — เป็น Thread เดียวกับ FreeRTOS Task ของเราหรือไม่?**

ตอบ `esp_http_server` รัน Handler บน Task ของเซิร์ฟเวอร์ HTTP ที่สร้างขึ้นแยกต่างหาก ไม่ใช่ Task เดียวกับ FreeRTOS Task ที่เราสร้างเอง จึงต้องระวังการเข้าถึงข้อมูลร่วมกัน

**3. การที่ Dashboard ใช้ `<meta http-equiv="refresh" content="2">` แทนที่จะใช้ JavaScript fetch() มีข้อดีและข้อเสียอย่างไร?**

ตอบ ข้อดีคือเขียนโค้ดง่าย ไม่ต้องเขียน JavaScript เพิ่ม และสามารถรีเฟรชข้อมูลได้ทุก 2 วินาที ส่วนข้อเสียคือหน้าเว็บโหลดใหม่ทั้งหมด ทำให้การแสดงผลกระตุกและใช้ทรัพยากรมากกว่า `fetch()` ซึ่งสามารถอัปเดตเฉพาะข้อมูลที่เปลี่ยนแปลงได้โดยไม่ต้องโหลดหน้าเว็บใหม่

## สรุปผลการทดลอง

จากการทดลองพบว่าสามารถสร้างระบบ IoT Sensor Dashboard ด้วย ESP32 ได้สำเร็จ โดยใช้ SoftAP สำหรับเชื่อมต่ออุปกรณ์ ใช้ FreeRTOS Queue สำหรับรับส่งข้อมูลระหว่าง Task และใช้ Mutex ป้องกันการเข้าถึงข้อมูลร่วมกัน นอกจากนี้ HTTP Server ยังสามารถเริ่มทำงานและให้บริการหน้า Dashboard รวมถึง JSON API ได้สำเร็จ
